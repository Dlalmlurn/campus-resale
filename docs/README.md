# Documentation Index

本目录保存校园二手交易系统的正式目标文档。

文档采用“合成基线 + 产品形态 + 领域契约 + 数据库设计 + 质量标准”的轻量结构。历史访谈中产生的细粒度 ADR 已并入 `00_project_baseline.md`，不再作为主阅读入口。

## 文档职责

| 文档 | 职责 |
| --- | --- |
| `00_project_baseline.md` | 合成基线：定义项目定位、正式主线、需求基线、技术口径、长期约束和正式边界。 |
| `01_project_shape.md` | 产品目标形态：定义入口、核心模块、页面、业务流和能力边界。 |
| `02_domain_contracts.md` | 领域契约：定义角色权限、领域对象、事件、接口族和一致性规则。 |
| `03_decision_backlog.md` | 决策收束记录：说明已访谈问题的收束状态和后续 ADR 粒度规则。 |
| `04_final_quality_criteria.md` | 最终质量标准：定义系统达到目标形态时应满足的检查项。 |
| `05_database_design.md` | 数据库设计：定义表分组、关键字段、状态枚举、约束索引、统计视图和迁移顺序。 |

## ADR

ADR 位于 `docs/adr/`，只记录会改变长期架构、模块边界、核心状态机、资金链路、治理链路、AI 使用边界、核心领域对象或关键一致性约束的分叉决策。

已被合成基线吸收的历史 ADR 归档在 `docs/adr/archive/`。归档 ADR 作为来源材料保留，不要求日常开发逐篇阅读。

## 补充规则

- 后续补充优先修改现有编号文档的对应章节。
- 单个问题、单条规则、单次访谈结论不新增文件。
- 新增编号文档只用于新的稳定专题，例如独立的安全基线、运维基线或外部系统接入基线。
- 新增 ADR 只用于存在长期分叉且会影响架构边界的选择。
- ADR 被正式吸收后，应在编号文档中留下结论，在 ADR 目录中保留来源说明即可。
