# ADR-001: 使用稀疏 ADR 管理长期决策

**Status:** accepted

## Decision

使用 `docs/adr/` 记录会长期影响项目结构、技术栈、数据链路、AI 使用边界、资金链路和治理方式的分叉决策。

ADR 采用稀疏策略：不为单个业务细则、字段、页面交互或可由正式编号文档推导出的规则单独创建文件。

## Context

项目需要同时保存三类内容：

- 项目宪章：系统使命、正式边界、架构选择和长期决策。
- 产品形态与领域契约：用户旅程、页面目标、角色权限、领域对象、事件、接口族和一致性规则。
- 分叉决策：会改变长期结构或关键链路的选择。

历史访谈曾产生较多细粒度 ADR。它们已经被合并进正式编号文档，只在 `archive/README.md` 中保留摘要。

## Alternatives

| 方案 | 结论 | 原因 |
| --- | --- | --- |
| 每个问题都创建 ADR | 不采用 | 文件数量会快速膨胀，阅读路径变重。 |
| 不使用 ADR | 不采用 | 技术栈、资金链、治理链和 AI 边界等长期选择缺少历史记录。 |
| 使用稀疏 ADR | 采用 | 主线口径集中在正式编号文档中，少数关键分叉保留独立记录。 |

## Rationale

项目宪章定义系统为什么存在以及长期边界。产品形态和领域契约定义用户体验、稳定对象和协作边界。ADR 只解释为什么选择某条长期路线。

这样既保留决策追溯，又避免把普通规则拆成大量小文件。

## Consequences

- 日常阅读以 `../正式文档/00_project_baseline.md` 为入口。
- 新 ADR 必须说明它改变了哪个长期边界。
- 字段名、页面交互、接口路径、提醒样式和局部校验顺序不进入 ADR。
- 历史细粒度 ADR 以归档摘要保留，不作为正式阅读入口。
