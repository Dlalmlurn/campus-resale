# 决策收束记录

本文件记录历史访谈问题如何收束。它不再作为持续追加问题的队列。

## 收束结论

历史访谈中的 A00-A21 已合并进 `00_project_baseline.md`，并在产品形态、领域契约和最终质量标准中保留必要检查点。

后续不默认继续逐个问题追加 ADR。只有当新问题会改变模块边界、核心状态机、资金链路、治理链路、AI 使用边界、核心领域对象或关键一致性约束时，才进入 ADR。

## 已吸收主题

| 主题 | 已进入基线的口径 |
| --- | --- |
| 校园认证 | 多因子可信度模型，姓名学号 40 分，院系 10 分，邮箱 10 分，学生证或校园卡 40 分；50 分进审核，60 分且审核通过开放完整交易权限。 |
| AI 使用边界 | AI 只进入商品发布和审核预检，规则服务为主路径，LLM 为可选优化项，不读取聊天、举报、认证材料和身份隐私资料。 |
| 文件与隐私 | 数据库存文件元数据，二进制进入统一文件存储层；敏感材料必要可见；管理员敏感访问留痕。 |
| 技术与部署 | Spring Boot、React、PostgreSQL；前端、后端、数据库和文件存储依赖支持 Docker 化运行。 |
| 会话与发现 | 私信实时通道采用 WebSocket；推荐采用可解释规则和统计排序，不使用敏感材料。 |
| 信用与统计 | 信用采用可解释变动记录聚合；后台统计以 PostgreSQL 视图、索引和聚合查询为主。 |
| 担保支付 | 支付采用担保式交易和模拟支付渠道，保留真实支付适配器接口。 |
| 订单占用与金额 | 买家创建订单时原子占用商品并冻结订单金额；支付单金额来自订单冻结金额。 |
| 完成确认与结算 | 买家确认完成是结算主触发；卖家完成确认请求后买家确认窗口为 48 小时，24 小时提醒一次。 |
| 退款与评价 | 支持全额和部分退款；退款金额不直接代表责任；全额退款关闭不评价，部分退款成交后可评价。 |
| 补充收束口径 | 单校配置、公开身份必要暴露、商品禁售、成色枚举、图片私信、站内正式通知、无平台钱包、模块化单体、REST JSON、MinIO/S3 兼容文件存储、公网云部署、PostgreSQL 搜索、PostgreSQL 聊天消息表和校园地点字典已进入基线。 |
| 外部补充稿筛选 | 时间窗口、收款方式、并发原子性、议价卡片、AI 工程参数、禁售路径、容量限制、取消关闭语义、评价举报、安全配置和毕业语义已压缩吸收；认证分值拆分和令牌刷新会话口径未采用。 |

## 粒度规则

普通字段、页面交互、提示文案、接口路径、提醒样式、局部校验顺序和能从既有基线推导出的规则，不进入 ADR。

这类内容应进入开发设计、接口说明或代码实现。
