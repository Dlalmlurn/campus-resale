#### R1 — 举报处理仍 500（意见 3 回归）✅ 已修

- **现象**：管理员处理举报后前端报"服务端处理失败"。
- **日志**：`DataIntegrityViolationException ... violates check constraint "ck_sensitive_access_logs_result"`，失败行 `result='SUCCESS'`。
- **根因**：[AuditLogRepository.recordSensitiveAccess](../backend/src/main/java/com/campusresale/platform/audit/AuditLogRepository.java) 写入的 `result` 由调用方传入，而 [N3GovernanceService.java:214](../backend/src/main/java/com/campusresale/governance/N3GovernanceService.java#L214)（处理举报证据）传的是 `"SUCCESS"`。但 [V1__foundation_schema.sql:153](../backend/src/main/resources/db/migration/V1__foundation_schema.sql#L153) 的约束只允许 `ALLOWED / DENIED / FAILED`。
- **波及面（同样传 `"SUCCESS"`，都会炸）**：`N3GovernanceService` 第 182/187/192/214/233 行（举报/申诉/退款队列查看、举报证据、申诉证据）、[OrderService.java:580](../backend/src/main/java/com/campusresale/order/OrderService.java#L580)（退款证据）。对照正确写法：`ConversationService:296` 与 `FileService:225` 用的是 `"ALLOWED"`。
- **修复**：把上述 `recordSensitiveAccess(...,"SUCCESS",...)` 统一改为 `"ALLOWED"`（语义：敏感资源访问被放行）。可顺手在 `recordSensitiveAccess` 入口对 `result` 做白名单断言，非法值早失败而不是落库炸。
- **验证**：新增一条**打到真实 Postgres** 的测试（`@SpringBootTest` + Testcontainers / 现有集成测试夹具），断言"处理举报"后 `sensitive_access_logs` 落库成功，且端到端处理举报返回 200。

#### R2 — 通知"只看未读"仍 500（意见 11 回归）✅ 已修

- **现象**：通知页点"只看未读"报服务端错误。
- **日志**：`BadSqlGrammarException ... read_at IS NULLORDER BY created_at DESC`。
- **根因**：[NotificationRepository.java:85-92](../backend/src/main/java/com/campusresale/notification/NotificationRepository.java#L85) 文本块拼接：`unreadClause = " AND read_at IS NULL"`（无结尾空格/换行），紧跟的文本块以 `ORDER BY` 开头，拼成 `read_at IS NULLORDER BY`。`countByReceiver`（106 行）因 `unreadClause` 在末尾未被影响，所以只有列表查询炸。
- **修复**：给 `unreadClause` 补结尾换行（如 `"\n                        AND read_at IS NULL\n"`），或把整段 SQL 改为不依赖文本块相邻拼接（推荐用单一 SQL + 条件参数，避免再踩拼接坑）。
- **验证**：补一条真实 DB 测试，断言 `findByReceiver(unreadOnly=true)` 能执行且只返回未读。**不要**再用 `@WebMvcTest` mock Service 来"验证"SQL。
