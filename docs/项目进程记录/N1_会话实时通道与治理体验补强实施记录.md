# N1 会话实时通道与治理体验补强实施记录

更新时间：2026-06-07

## 覆盖范围

- N1-2 WebSocket 实时通道：`/ws/conversations` 复用 `CR_SESSION`，连接后订阅会话并校验参与者权限。
- N1-3 私信图片与附件：新增 `MESSAGE_IMAGE` 文件用途、`message_attachments` 绑定、图片消息展示和上传错误态。
- N1-4 会话治理与体验：会话归档/屏蔽、未读数、列表高亮、移动端单列布局、议价过期口径和管理员敏感访问日志。

## 演示脚本

1. 启动项目并分别用买家、卖家两个浏览器登录已认证学生账号。
2. 买家从商品详情进入会话，卖家打开同一会话详情页。
3. 买家发送文本消息，卖家页面应在不刷新情况下实时追加；断开网络或关闭 WebSocket 后，页面显示“轮询补偿”，重新进入或等待轮询会补拉缺失消息。
4. 买家上传一张 JPEG/PNG/WebP 私信图片并发送，卖家会话页应展示图片消息。
5. 买家发起议价，卖家实时看到议价卡片；卖家接受或拒绝后，买家实时看到系统卡片和卡片状态变化。
6. 卖家在未打开会话时收到消息，再进入会话列表，应看到未读数高亮；打开详情后未读会话通知被标记为已读。
7. 任一参与者点击归档后，该会话从自己的列表隐藏；点击屏蔽后会话进入 `BLOCKED`，双方不能继续发送消息或议价。
8. 管理员访问 `/api/admin/conversations/{id}?reason=纠纷核查` 或查看私信图片原件，应写入 `sensitive_access_logs`，目标类型分别为 `PRIVATE_MESSAGE` 和 `PRIVATE_MESSAGE_IMAGE`。

## 状态口径

- 消息、图片和系统卡片始终先写入数据库，再通过事务提交后的 WebSocket 事件推送。
- 数据库通知继续保留，作为离线补偿和未读策略来源。
- 重连补偿通过 `GET /api/conversations/{id}/messages?afterId={lastMessageId}` 拉取缺失消息。
- 议价卡片默认 24 小时过期；过期的 `PENDING` 卡片在列表/详情读取和接受/拒绝前转为 `EXPIRED`。
- 已关闭或已取消订单不阻止重新议价；仍进行中的订单会阻止继续议价或接受议价。
