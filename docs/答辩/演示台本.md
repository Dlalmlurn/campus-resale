# 校园二手交易平台 · 答辩演示台本

本台本给出一条从登录到交易、治理、AI 辅助、后台审计的**完整可点击演示路径**，按顺序照做即可覆盖各阶段核心能力。建议演示前先按"环境准备"启动空库，保证种子数据齐全。

## 演示账号（统一密码 `520zikejiang`）

| 用户名 | 角色 | 演示用途 |
| --- | --- | --- |
| `seller_demo` | 已认证学生 | 卖家：名下有在售商品，演示发布、AI 辅助、卖家确认、完成。 |
| `buyer_demo` | 已认证学生 | 买家：演示下单、模拟支付、完成确认、评价、收藏关注。 |
| `student_demo` | 已认证学生 | 备用认证学生，名下另有 3 件演示商品。 |
| `user_demo` | 普通注册用户 | 演示"未认证不能交易"的拦截。 |
| `content_admin` | 内容管理员 | 后台：认证/商品审核、统计、审计日志、治理队列。 |
| `super_admin` | 超级管理员 | 单端登录、资金后台等更高权限演示。 |

> 前端开发模式右上角有"买家/卖家/管理员"一键切换按钮（仅 `npm run dev` 可见），对应 `buyer_demo / seller_demo / content_admin`。

## 环境准备

```bash
docker compose down -v          # 清空旧库，保证从 V1 重新迁移
docker compose up --build
# 前端 http://localhost:3000  后端 http://localhost:8080/api/health
```

如 3000 端口被占用：`FRONTEND_PORT=3300 docker compose up --build`。

## 演示路径（约 10 分钟）

### 1. 商品发现与个性化（N4 发现增强）
1. 打开首页"商品"，展示在售商品卡片。
2. 指出每张卡片底部的**推荐理由**（后端 `RECOMMENDED` 排序返回）。
3. 用关键词（如"考研"/"计算器"）搜索，演示分类筛选。
4. 在任意卡片点击"收藏"和"关注卖家"，右上角"通知/治理"可见联动。

### 2. 买家下单到完成（N1 最小交易闭环）
1. 用 `buyer_demo` 登录。
2. 进入 seller_demo 的"科学计算器 FX-991"详情页，点击"立即下单"，选择交易地点与见面时间，提交订单。
3. 切到 `seller_demo`：进入"订单"，对该订单点击"卖家确认"。
4. 切回 `buyer_demo`：进入订单，"模拟支付"→ 资金进入托管（PAYMENT_ESCROWED）。
5. 双方"完成确认"，订单进入 COMPLETED，结算状态推进。
6. `buyer_demo` 对订单提交最小评价。
7. 全程到"通知"页查看订单创建、卖家确认、支付托管、完成等站内通知。

### 3. 会话与议价（N1 实时通道）
1. 商品详情页点击"联系卖家"建立会话。
2. 在会话内发送消息、发起议价卡片；另一端实时收到（WebSocket）。

### 4. AI 发布辅助（N4，规则引擎 + 可选 DeepSeek）
1. 用 `seller_demo` 进入"发布"页，填写商品标题、描述、价格。
2. 点击"生成优化建议"，展示：优化标题/描述、建议分类、标签、**风险等级**、推荐理由、审核提醒。
3. 注意建议面板上的来源徽章：未配置 LLM 时显示"规则引擎"，配置 DeepSeek 后显示"AI 模型生成"。
4. 用包含"代写"等高风险词的文案再生成一次：风险判为 HIGH，"通知"页出现 `AI_REVIEW_REMINDER`。
5. 强调安全边界：**AI 只给建议，不自动审核/下架/处罚**；即使接入 LLM，规则引擎对高风险词仍强制兜底，风险不会被 LLM 降级。

### 5. 治理闭环（N3）
1. 用 `buyer_demo` 在商品/订单上提交**举报**，上传证据。
2. 切 `content_admin` 进入"治理"队列：处理举报（成立可联动下架/订单关闭/信用扣减/处罚）。
3. 演示**申诉**：被处罚方提交申诉，管理员通过后反向修正信用与处罚影响。
4. 查看**信用摘要**页：对外标签 + 内部等级，来源于履约、评价、举报处罚、申诉修正。

### 6. 后台验收（N2）
1. 用 `content_admin` 进入"后台"：
   - 数据看板：订单/支付/结算统计。
   - 认证审核、商品审核队列。
   - 审计日志：关键操作可追溯（含 AI 辅助 `AI_GOODS_ASSIST`、敏感材料访问）。
   - 资金管理入口。
2. 强调：所有关键状态变化由后端决定并留痕，前端不能伪造。

### 7. 权限边界快速演示
1. 用 `user_demo`（未认证）尝试下单/发布 → 被拦截到认证页。
2. 用普通用户访问 `#/admin` → 无后台权限提示。

## 应答要点

- **状态机/幂等/行锁**：下单用 `SELECT ... FOR UPDATE` 占用商品，避免超卖；支付/结算状态单向推进。
- **权限隔离**：Filter 识别登录态 + Interceptor/注解校验角色与交易资格；写请求做 Origin/Referer CSRF 校验。
- **敏感数据**：校园认证材料 `ADMIN_ONLY`，管理员查看原件写 `sensitive_access_logs`。
- **AI 安全**：规则兜底 + 审计留痕 + 频率限制（默认每人每天 5 次）。
- **可部署**：见 [`docs/部署/HTTPS部署与运维说明.md`](../部署/HTTPS部署与运维说明.md)，一条命令起 HTTPS 生产栈。

参见配套的 [验收清单](验收清单.md) 与 [截图清单](截图清单.md)。
